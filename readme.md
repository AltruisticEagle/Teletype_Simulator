## Project summary
Originally, this project was meant to be a teletype computer simulator, simulating the remote-access system for computers back in the 1960s and 70s where a computer is accessed remotely through a teletype computer capable of communicating with the computer with code. Imagine if the computer running your code is, say, 20 kilometres away from you; the teletype serves as your terminal and IDE to that remote computer that you can access.

However, I think it's more appropriate to call this project a basic BASIC interpreter, seeing as two-thirds of the source code for this project is contained in interpreter.py. And therein lies the simulation - you're coding in BASIC, while the architecture of this project attempts to simulate what that was like with 1970s IT infrastructure.

## Download and running
run, in a terminal, ```pipx install teletype_simulator```, then run ```teletype-sim``` after pipx installs the package; you should then see the terminal output "OUTPUT > Configuring BASIC interpreter...", which is a purely aesthetic feature that signals that the program is running normally.

I am aware that Windows OS might have trouble running this program, as it is packaged in the same way as the Linguistics Project on my profile; it seems to work without issues when it is being operated in a Linux/WSL environment, something I cannot solve due to the fact I don't have a Windows PC capable of performing the said test for me. In any case, I have made sure this sequence of commands works on my local Mac VS Code several times.

## Tips for using the basic interpreter
1. Having END at the end of your script terminates the execution of the program, unless you want it to keep looping. In this case, be advised that if none of your scripts contains END, you will be forced to use Keyboard_Interrupt or EOFError to quit the program. 
2. The way I programmed this project, I don't think you actually need to put quotes around strings or integers.
